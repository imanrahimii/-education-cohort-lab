Higher education outcomes practice lab

EL1 Data Analyst interview preparation · Azure Databricks, SQL, Python and GitHub Actions

Your brief. Compare domestic and international student outcomes and explain what the evidence supports. All records and results in this project are synthetic. Agree on eligibility, access, linkage and disclosure rules with data custodians before using official data.

1. Create the project area

  1. Unzip the project. In your existing Azure Databricks Workspace, make a folder for the four notebooks. Import each .py file from notebooks/ as a Databricks source notebook.
  2. Open 00_setup, attach Python-capable compute with Unity Catalog access, and run its first cell to create the widgets. Set catalog to a writable catalog. For your earlier workspace this was dbw_sales_iman01. Keep education_cohort_lab as the schema and run all cells. If catalog validation errors on the initial run, set the widget and rerun.
  3. In Catalog Explorer, open your catalog, then education_cohort_lab, then the incoming volume. Upload the three CSVs from data/ directly into that volume. The printed path should end with /education_cohort_lab/incoming.

Workspace holds the notebook code. Compute runs it. The catalog and schema provide the names and access boundary for tables and volumes. The volume is where this project reads input files.

2. Run the ETL and verify a late correction

Use the same catalog and schema widgets in each notebook. Run 01_ingest with batch=1, then run 02_transform_report. Ingests are cumulative snapshot rebuilds in this lab. Keep a single writer and avoid overlapping runs or switching back to batch 1 after publishing batch 2.

StageWhat happens
Extract / BronzeRead CSVs from the volume and write raw Delta tables. Bronze keeps duplicate deliveries.
Transform / SilverQuarantine the malformed student row, collapse identical deliveries, and select the latest valid revision. Conflicting latest student revisions and conflicting survey responses are excluded by the sample SQL. A real workflow should explicitly log and review conflicts before releasing results.
Load / GoldBuild cohort and age-band counts for continuation, satisfaction and employment. A left join keeps students without survey responses in the eligible total. Rates divide positive outcomes by observed outcomes.

Run the two notebooks again with batch=2. Then repeat batch 2 and compare results. In a SQL cell, replace YOUR_CATALOG with your catalog and run:

3. Compare outcomes in Python

Run 03_analyse after batch 2. It works from the small Gold summary and applies the same pooled age distribution to both cohorts. This helps you see how the comparison changes when the cohorts are given the same age mix. The gap is domestic minus international in percentage points.

OutcomeObservedCrude gapAge-adjusted gapApproximate 95% interval

Employment27415.6215.434.28 to 26.58

The lab treats everyone as survey-eligible to make missingness visible. Real employment analysis needs its own target population, eligibility and follow-up window. The approximate intervals treat the pooled age weights as fixed and responses as independent. P-values are individual and unadjusted for multiple comparisons. Real survey inference also needs the applicable design, weighting, clustering and nonresponse approach. Age adjustment alone cannot identify a causal effect.

The notebook demonstrates a count-based disclosure screen with an arbitrary practice threshold of 10. Before any release, agree on the applicable rules and review linked tables and residual cells for possible disclosure.

4. Run the pipeline as a Databricks Job

In Lakeflow Jobs, create a job with these Notebook tasks, using the imported notebooks as their Workspace source:

  1. Ingest → 01_ingest. Pass catalog, schema and batch=2.
  2. Transform and report → 02_transform_report. Pass catalog and schema. Set it to depend on Ingest.
  3. Analyse → 03_analyse. Pass catalog and schema. Set it to depend on Transform and report.

Use Python-capable compute that can access the lab schema and volume. Run on demand first and open the task outputs. The exercise uses static batch files. A schedule would repeat the selected batch until you provide new inputs and change how the batch is selected.

In GitHub, open Actions → Education cohort analysis CI → test. Expand the test step and look for Ran 5 tests and OK. GitHub executes the shared reporting SQL against SQLite fixtures and tests the Python statistics and notebook syntax. Your Databricks Job executes the notebooks on Databricks compute and writes Delta tables. Check the results of both runs.

For an interview demo, temporarily change COUNT(result) AS observed to COUNT(*) AS observed in queries.py. Run python build.py and then python -m unittest discover -s tests -v locally. Explain the failure, restore the original line and regenerate. The tests use Python 3.11 and the standard library.

6. Practise the interview briefing

Why did Monday's continuation rate change after the correction arrived?
The eligible population stayed at 800. We gained 31 known outcomes. I would record the reporting cutoff and batch used for each release, then reconcile the corrected results against the previous figures.
Can we brief the employment gap as a policy finding?
The synthetic respondent gap remains after age adjustment, but only 274 of 800 students have observed employment outcomes. I would check response patterns by cohort, confirm the target population and test whether the result is sensitive to plausible outcomes for nonrespondents before drawing a policy conclusion.
How would you deliver the work under deadline?
Agree on the questions, definitions and release rules at inception. Deliver validated cohort counts early, agree which comparisons go into the draft, and reserve review time for methodology, disclosure and policy wording.

Use REPORT_EXAMPLE.md to rehearse a one-minute answer. Then write your own brief with one result, one limitation, and one recommended action.
